## 모든 화면에 같은 규칙
### 말
- 한 뜻 = 한 말. 같은 것을 다른 화면에서 다른 말로 쓰지 않는다 (구매함 ↔ 가진 것, 예고 ↔ 공지 · 공고, 채널 ↔ IP, 지우기 ↔ 삭제, 복원 ↔ 되살리기).
- 공식 회사 · 한국 큰 가게가 실제로 쓰는 말을 고른다 (반다이 스피리츠 · 포켓몬스토어 · LEGO.com/ko-kr · 닌텐도 코리아 · 하비팩토리 · 타카라토미). 직역 · 지은 말 · 내부 코드 · 개발 말(빌드 · 함수 · 표 · IP)은 화면에 쓰지 않는다.
- 공식 등급 코드 · 로고 이름은 그대로 (PG · HG · ROBOT魂 · METAL BUILD …) — 한국에 한국어 이름이 굳은 것만 한글 (메가사이즈 · 풀 메카닉스 · 하로프라 · 초합금 · 무등급).
- 한국어 화면에 일본어 글자(가나 · 再販 같은 한자)를 쓰지 않는다. 데이터가 일본어뿐이면 [data-names.md](data-names.md) 의 고르는 순서를 따른다.

### 말투 · 문장부호
| | 한국어 | 中文 |
| --- | --- | --- |
| 문장 | 해요체 `…했어요` · `…예요` · `…세요` | 口语, `你` |
| 버튼 · 칸 | 짧은 명사구 `이름 바꾸기` · `수정 저장` | 短词 `改名` · `保存修改` |
| 칸 안 상태 | `없음` · `지움` · `켜짐` | `没有` · `已删除` · `开着` |
| 도움말 줄 | 명사구 · 해요체 (`누르면 켜기 · 다시 누르면 끄기`) — 해라체 `…한다` ✗ | 短句 |
| 마침표 | 한 문장이면 없음, 여러 문장 설명만 `.` | 提示句不加句号，多句说明用 `。` |
| 나열 | ` · ` (앞뒤 공백) | ` · ` |
| 이름 | 「{name}」, 뒤 조사 없이 (`「{name}」 지웠어요`) | 「{name}」, 和中文之间不加空格 (`已删除「{name}」`) |
| 괄호 | 반각 `( )` | 全角 `（）` |
| 범위 | `3만–10만원` (줄표 `–` 앞뒤 공백 없음) | `3万–10万韩元` |
| 진행 중 | `… 중` (`번역 중 {done}/{total}`) | `正在…` |
| 실패 | `…하지 못했어요` | `没能…` |
| 확인 질문 | `…할까요?` | `要…吗？` |

- 조사를 기계로 붙이지 않는다: `을(를)` · `은(는)` · `이(가)` · 값 뒤 고정 `와` · `가` ✗. 조사가 필요 없는 모양으로 다시 쓴다 (`「{q}」에 맞는 상품이 없어요` · `보유한 {slot} 없음` · `{channel} 상품이 아직 없어요`).
- 의존 명사 · 조사는 붙인다: `{date}쯤` · `{from}부터` · `{to}까지` · `…처럼`.
- 문장을 꾸미는 말로 끝내지 않는다: `최근 본` ✗ → `최근 본 상품`.

### 숫자
- 세는 말: `{n}개` · `{n}건` · `{n}장`(사진) = `{n} 个` · `{n} 件`/`{n} 条` · `{n} 张` (중국어는 숫자와 양사 사이 한 칸).
- 둘러보는 화면(분류 칸 · 필터 칸 · 목록 머리 · 세대 부제 · 탭)에 상품 개수를 쓰지 않는다. 내 것의 수(구매함 · 좋아요 · 보유 · 수집 n/m)와 `n개 보기` 만.
- 값이 0 인 필터 칸은 흐리게(회색) 두지 않고 숨긴다.
- 정가는 그 나라 돈 그대로 (`₩19,000 · ¥1,650`). 환산 · 추정 가격은 쓰지 않는다. 내 돈은 `{n}원` · `{n} 韩元`.
- 날짜: 목록 `11.14` · `11.14 21:00`, 상세 `2026-12-15`, 중국어 `{m}月{d}日`.

### 데이터 값
- 코드가 비교 · 저장하는 값(k.line · k.type · k.goodsKind · k.subline · 묶음 키 · 알림 조건)은 한국어 옛 모양 그대로 둔다. 화면에 보일 때만 `dataLabel(값)` 으로 표준 이름 + 번역 ([data-names.md](data-names.md)). `tr(k.line)` 처럼 데이터 값을 `tr` 로 찾지 않는다 (debug 에서 빠진 번역으로 잡힌다).
- 묶음 제목 · 세대 묶음 이름(`_Sec.title` · `worldSectionOf`)은 보이기만 하는 글이라 바로 표준 이름으로 쓰고 `tr`.
- 예고 출처는 `sourceLabel(값)`, 알림 기록처럼 남겨 두는 곳은 `sourceName(값)` (언어 없는 표준 이름 — 보일 때 번역).
- 오류 글은 한국어로 던지고 화면에서 `errorText(e)` (`lib/widgets/feedback.dart`) — `'$e'` 를 그대로 보이면 `FormatException:` · `Bad state:` 머리가 붙는다.

### 새 말 넣는 순서
1. terms.md 에 한 줄 (한국어 · 中文 · 메모 — 왜 이 말인지, 쓰지 않는 말).
2. 그 화면 묶음 문서(이 폴더)의 어휘 표 · 예에 한 줄.
3. 코드에서 `tr('…')` · `trf('…', {...})`, 번역은 그 화면의 zh 파일 (`lib/l10n/zh/<묶음>.dart`) — 두 화면 이상이 쓰면 `common.dart`.
4. 같은 한국어가 두 zh 파일에 있으면 번역이 같아야 한다 (뒤 파일이 이긴다).

### 확인
- `flutter test test/l10n_coverage_test.dart` — `tr` · `trf` · `NoticePart.key` 로 감싼 한국어가 모두 번역 표에 있고, 번역에 한글이 없고, `{자리}` 가 같고, 묶음끼리 번역이 어긋나지 않는다.
- `flutter test test/l10n_screens_zh_test.dart` 와 묶음별 `test/l10n_*_test.dart` — 중국어 화면을 실제로 그려 한글이 남은 곳을 찾는다.
- 화면 테스트는 글자가 아니라 `Key` · 아이콘 · 타입으로 찾는다 (글을 바꿔도 테스트가 그대로 돌게).
- `dart analyze lib test tool` 0 issues, 고친 파일만 `dart format -l 120`.
- 마지막에 주 세션이 전체 diff 의 말을 이 문서 · terms.md 와 맞춘 뒤 커밋한다.
